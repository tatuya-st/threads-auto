## 2. Threadsの道具（threads-cli）の棚卸し（2026-11-16 楓）

- 投稿：publish-post（本文・画像/動画1〜20件・返信）。返信先の制御（全員／フォロー中／メンションのみ／投稿者だけ／フォロワーのみ）と「返信の承認制」を付けられる
- 返信の管理：pending-replies（承認待ち一覧）、review-pending-reply（承認・却下）、hide-reply（非表示）
- 読む：投稿・コメント・いいねした人、フォロワー／フォロー中、プロフィール、自分の投稿・返信・メディア
- 数字：insights-overview、post-insights（投稿ごと）、top-posts
- 発見：search、trends、feed、feedback-hub
- dear-algo-whisper：アルゴリズムへの要望メッセージを送る機能がある（未使用。使い方と効果は調査中）
- 無い：引用・リポスト・いいね・削除・予約投稿のコマンド

## 5. Threads APIの裏側（2026-11-16夜、並行調査の結果。Meta公式ドキュメントに基づく複数資料で一致）

- 投稿：テキスト500文字／画像／動画（最大300秒）／カルーセル2〜20点。メディアは公開URL渡しのみ
- **投票（ポール）がAPIで可能**（テキスト投稿のみ、選択肢2〜4個）。トピックタグ（1投稿1つ）、リンク添付、スポイラー、ゴースト投稿（24時間で消える）も指定可能
- **引用・リポストがAPIで可能**（リポストの取り消しだけ不可）
- **削除がAPIで可能**（専用権限 threads_delete が必要）。投稿後の本文編集は不可（削除→再投稿のみ）
- いいねはAPIでも不可。下書き機能なし。予約投稿はAPIでは不可（アプリ内蔵の予約は別にある）
- 上限（24時間・プロフィール単位）：投稿250件／返信1,000件／削除100件。残量はAPIで確認可能
- 注意：私たちの threads-cli には引用・リポスト・削除・投票のコマンドが無い。APIでできることと道具でできることの差がここにある（京の tools で実装できるかが次の論点）

## 6. Threadsの数字とクリック（同・並行調査＋楓の実測）
- 投稿ごと：表示・いいね・返信・リポスト・引用・シェアの6項目のみ
- アカウント全体：APIには **clicks（リンクごとのクリック数）が実在する**（2025-07-02追加）。アプリ表示から外れただけで、APIには残っている
- ただし楓のCLIの insights-overview には clicks が出てこない（今夜実測）。京の insights.json の clicks 全部0も、読む場所が違う可能性が高い → 京の tools で threads_insights の clicks を直接読むテストが次の一手
- **【2026-11-20 京の回答で確定】京の道具では clicks は読める**：tools/publish.py の link_clicks が threads_insights の metric=clicks を直接読んでおり、state/insights.json（11:31版）にも入っている（ROOM items 30・collections 1、A8と楽天の各リンクは0）。ただしアカウント単位の「リンクURLごと」の合計（link_total_values）で、投稿IDごとではない。投稿ごとにリンクを変えれば実質投稿単位で測れる
- Threadsのフォロワー属性（今夜実測）：25-34歳が最多28.4%、日本92.8%。IG（45-54最多）とは層が違う
